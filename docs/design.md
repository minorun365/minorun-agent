# 作りの要点

## 入口

ログインなしで公開するため、断る仕組みを手前から順に置いています。手前ほど安く断れます。

| 段 | 断るもの |
|---|---|
| CloudFront の WAF | 同じ IP からの大量の送信、AWS マネージドの IP 評判リスト・既知の攻撃 |
| 入口の Gateway の Lambda インターセプター | 匿名IDの形が不正、1,000字を超える質問、匿名IDごとの1分5件・1日30件を超えた分、停止スイッチが入っているとき |
| 入口の Gateway の回数制限 | 費用の安全網として、全体で1分60件を超えた分 |

認証なし（`authorizerType: NONE`）の Gateway では、ヘッダーごとの回数制限を作れません。そのため、匿名IDごとの回数はインターセプターが DynamoDB で数え、Gateway の回数制限は全体の上限にしています。断るときは Runtime を呼ばず、日本語の理由を付けて返します。

CloudFront の `/api/chat` へのリクエストは、CloudFront Function で Gateway の `/minorun/invocations` へ書き換え、Gateway の HTTP ターゲットから Runtime へ中継します。SSE もこの経路のまま逐次返ります。会話IDはヘッダー `X-Amzn-Bedrock-AgentCore-Runtime-Session-Id` に載せて送ると Runtime へ渡り、同じ会話として扱われます。Runtime のリソースポリシーでは、入口の Gateway のロールからの呼び出しに絞って許可しています。

任意で Google ログインした人は、インターセプターが Cognito のアクセストークンを確かめて上限を緩め、利用者を区別するハッシュを本文に入れて Runtime へ渡します。

## ツール

| ツール | 中身 |
|---|---|
| `now` | ラスベガスと日本の日時、会期まであと何日か |
| `search_sessions` | 公式セッションカタログの控えを手元で検索し、回答後に公式 API で照合する |
| `search_2026`・`search_past` | 2026年分とそれより前のナレッジベース。年の絞り込みは Gateway 側で固定 |
| `search_web` | AgentCore Web Search |
| `search_recent` | Brave Search による直近1週間に絞った検索。API キーは AgentCore Identity の保管庫から読む |
| `search_whats_new`・`search_aws_blog` | AWS の What's New と AWS ブログ |
| `get_announcements` | 会期中に現地から足す速報。S3 の JSON に `knowledge/tools/announce.py` で足す |
| `show_map` | `agent/maps.json` を使い、回答の吹き出しに地図や図を添える |
| `make_slides` | ログインした人が渡した記事のURLから解説スライドを作り始める。詳しくは下の「URLからスライド」 |

ナレッジベースと AgentCore Web Search は、MCP と IAM 認証を使うツールの Gateway 越しに呼びます。1回の質問でツールを呼べる回数には上限を付けています。

## 回答の形

回答は60〜120字・2〜3文を基本にし、見出しや表は使いません。出典はその情報を使った文の末尾に `[ラベル](URL)` で付け、画面側で小さなラベルとして表示します。続きは「次の質問の候補」から聞いてもらう形で、候補は質問が届いた時点で Haiku が回答と並行して3つ作ります。

Runtime から画面へ送る SSE の形式は `agent/app.py` の冒頭に定義しており、イベントの種類は topic・tool・text・map・slides・catalog_update・suggest・error・done です。

## URLからスライド

記事のURLと「スライドにして」を送ると、ツール `make_slides` が DynamoDB で利用回数を数えます。カウントの単位は、ログインした人が1人1日、ログインしていない人が匿名IDと送信元IPごとの1日、さらに全体での1日です。確認が通ると、進み具合のファイル `s/<番号>/status.json` を S3 に置き、`slides/` にあるスライド作成機能の Lambda を非同期で起こします。CloudFront の読み取りは60秒で切れるため、生成の完了を1回の応答内では待ちません。

2026-11-21 から、スライド作成機能は記事を読み込んだあとの執筆をマネージドのエージェントである AgentCore Harness に任せています。Harness の入れ物はスライド作成と同じコンテナです。エージェントはシェル操作とファイル操作のツールを使い、Marp の Markdown を書いて `slides/bin/check_deck.py` で画像へ書き出して余白を測り、出力された画像を `read` で開いて目で確認し、直す工程を自分で繰り返します。アーキテクチャ図は Python の diagrams で描き、挿絵は非公開の S3 に置いた画像一式から入れ物へ取り込んで選び、リポジトリには含めません。選び方と描き方はスキルに書き、エージェントは要るときに読みます。書き方の指示とスキルは `slides/core/` に分けてあり、公開版には見本だけを置いて、作り手が本番で使っている中身は公開していません。詳細は `slides/core/README.md` にあります。書き上げたものは S3 の `work/<番号>/` に置かせ、スライド作成機能が受け取ります。ここで、使える HTML のタグと、用意した挿絵およびその1本のために描いた図へ画像を絞ってから出力し直し、余白を測ってページごとの画像、Xのカード用の表紙画像、めくれるビューアを S3 に置きます。書き出し中は手元のファイル以外への通信を止めています。Harness を使えなかったときは、従来どおり Opus に1回書かせて測り、崩れたスライドだけ1回直させます。

モデルは呼び出すたびに選びます。ふだんは Claude API の Opus 5.5 を使い、Max プランに付く月 $100 の API クレジットから払います。キーは AgentCore Identity の API キー資格情報 `claude-api` に置き、今月の使用額が $90 の線に近づいたら Bedrock の Opus 5.5 へ切り替えます。クレジットの残高を直接読む API が無いため、回答側が Claude API で払った会話の表の usage.calls と、スライド作成機能が払った回数の表の `credit#slides#<期>` を、`slides/credit.py` が足し上げます。Claude API で失敗したら同じセッションのまま Bedrock を指定して続きを書かせ、クレジット切れなどの失敗ならその期の残りは Bedrock へ固定します。回答のエージェントも同じ台帳を `agent/credit.py` で5分に1回読み、線を超えたら Bedrock だけで答えます。回答側でクレジット切れを受けたときは台帳に止めた印として `credit#off#<期>` を立て、スライド作成機能もその期の残りは Bedrock へ切り替えます。Harness のシェルには実行ロールの権限がそのまま入るため、ロールに渡すのはモデルの呼び出し、キーの読み出し、`work/*` への書き込みに絞っています。Harness のメモリは切ってあり、記事の本文と頼んだ人の一言は残りません。

画面は3秒おきに `status.json` を確認して4つの段階を順に更新し、できたら表紙のサムネイルへ切り替えます。ビューアは CloudFront の `/s/*` から配信し、URL を知っている人だけが開ける設定にして検索には出しません。見た目は `slides/theme/minorun-glass.css` のテーマで定義しており、使えるクラスは `slides/theme/README.md` にまとめています。

## セッション情報の鮮度

公式カタログの全件の控えを S3 に置き、Lambda が定期的に取り直します。Runtime は会話の開始時に控えを読み込み、手元で検索してすぐ答えます。あわせて同じ検索を裏で公式 API へ投げておき、回答を流し終えたら控えと突き合わせます。日時や部屋の変更や新しいセッションがあれば、モデルには書かせず決まった文面で追記し、見つけた変更は控えにも書き戻します。

## 会話の文脈

1回答えるごとに、やり取りとこれまでの話題の要約を圧縮して AgentCore Memory に保存し、Runtime の入れ物が替わったときは最新の状態から戻します。話題が変わったら前の話題を Haiku で要約して蓄積した要約に足し、直近の文脈から外します。前の質問の検索結果も短い一文に置き換えて文脈を軽くします。

ページを開いた時点で `{"warmup": true}` を送り、会話の入れ物を先に起こしておくと、最初の答えが出るまでの時間が短くなります。

## 記録と見張り

1問1行を DynamoDB に保存します。書く前に、メールアドレスと電話番号の形をした文字列を伏せます。表のストリームを受ける Lambda が2つあり、1つは最初の文字までの時間などを CloudWatch のメトリクスに出し、もう1つは Haiku で質問を仕分け、話題の外・指示の書き換えの試み・個人情報などに当たる要注意のものをメールで知らせます。

ほかに、CloudWatch のダッシュボード、エラーと費用のアラーム、AWS Budgets、AgentCore Evaluations のオンライン評価を MinorunWatch スタックにまとめています。利用量と概算コストは、合言葉つきの Lambda 関数 URL のページで見られます。
